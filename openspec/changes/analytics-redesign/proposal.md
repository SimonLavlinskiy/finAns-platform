# Новый раздел «Аналитика»: «Обзор месяца» и «Планирование»

## Зачем

Сейчас `/analytics` состоит из разрозненных экспериментальных виджетов (индекс свободы, Sankey,
прогноз баланса, инсайты и т.д.). Они не отвечают на два главных вопроса заказчика: «куда ушли
деньги в этом месяце» и «на что хватит в следующем». ТЗ v1.2 от 22.10.2026 (`TZ-analytics-finAnns.md`,
прототип `analytics-prototype.html`) закрывает все вопросы и описывает замену страницы целиком.

## Что меняется

- **BREAKING (UI)** Страница `/analytics` заменяется новым разделом с двумя вкладками: «Обзор месяца»
  (по умолчанию) и «Планирование». Последняя открытая вкладка запоминается для пользователя.
- Со страницы убираются старые блоки: инсайты, «Индекс свободы», «Жёсткость бюджета», «Прогноз баланса»,
  Sankey, «Когда я смогу купить?», «Календарь по настроению трат», старое «Сравнение периодов» и
  старый блок «Лимиты трат». Их компоненты и эндпоинты **остаются в коде**, просто не выводятся.
- Шапка: заголовок, подзаголовок, переключатель месяца `‹ Октябрь 2026 ›` (от первого месяца с
  операциями до текущего). Кнопки «+ Операция» нет.
- Блок 1 «Доходы и расходы сейчас»: полоса с тремя состояниями (свободно / ровно / перерасход), список
  категорий, плашка с цифрами и «Можно тратить в день».
- Блок 2 «Расходы по категориям и лимиты»: четыре сводные плашки, таблица всех расходных категорий
  с заполнением лимита, остатком, inline-редактированием лимита и раскрытием подкатегорий; сортировка
  «По заполнению лимита» / «По сумме».
- Блок 3 «Динамика доходов и расходов»: переключатель года, сводка за год, таблица месяцев с выделением
  и сравнение двух месяцев через собственные выпадающие списки.
- Вкладка «Планирование»: планируемый доход, регулярные платежи следующего месяца, плановые расходы по
  категориям с «Минимумом», карточка «Что останется». Данные общие для проекта и хранятся на сервере.
- **BREAKING (API)** Лимиты: один ежемесячный лимит на категорию; `PUT/DELETE /spending-limits/{categoryId}`.
  Старые эндпоинты по `id` остаются для совместимости.
- **BREAKING (данные)** Удаление категории становится мягким: у тега появляется `deleted_at`, операции
  сохраняют ссылку на него. Удалённая категория видна в аналитике только в месяцах, когда она существовала.
- У тега появляются `kind` (`expense`/`income`) и `order`. Категория «Доход» не участвует в расходных блоках.
- Новые эндпоинты: `GET /analytics/month`, `GET /analytics/year`, `GET /analytics/range`, `GET/PUT /planner`.
- Новый CSS-токен `--over` (ярко-красный для перерасхода), если подходящего токена в дизайн-системе нет.
- Синхронизация: после изменения операций, лимитов, категорий или регулярных платежей сбрасывается кэш
  `analytics`, `tags`, `spending-limits`, `planner`, и раздел пересчитывается без перезагрузки.

## Non-цели

- Изменения других страниц, кроме тех, что нужны для синхронизации (цвет категории и мягкое удаление
  в настройках проекта, инвалидация кэша после мутаций).
- Удаление старых аналитических компонентов и эндпоинтов из кода.
- Лимиты по отдельным месяцам, недельные и произвольные периоды лимитов в новом UI.
- Личное (не проектное) планирование, история версий планирования, разрешение конфликтов сложнее
  «последний записавший побеждает».
- Отдельный учёт возвратов: пока они считаются доходом.
- Добавление и удаление категорий из аналитики.

## Capabilities

### Новые capabilities
- `analytics-layout`: каркас раздела. Шапка, переключатель месяца, вкладки с запоминанием, дизайн-система,
  формат денег, синхронизация и инвалидация, состояния загрузки и ошибок, адаптивность, доступность,
  скрытие старых блоков. Создаст `specs/analytics-layout/spec.md`.
- `analytics-month-overview`: блок 1 «Доходы и расходы сейчас» и API `GET /analytics/month`.
  Создаст `specs/analytics-month-overview/spec.md`.
- `analytics-category-limits`: блок 2 «Расходы по категориям и лимиты» (сводки, таблица, редактирование
  лимита, подкатегории, сортировка). Создаст `specs/analytics-category-limits/spec.md`.
- `analytics-dynamics`: блок 3 «Динамика доходов и расходов» (год, сводка, таблица месяцев, выделение,
  сравнение, выпадающие списки) и API `GET /analytics/year`. Создаст `specs/analytics-dynamics/spec.md`.
- `budget-planner`: вкладка «Планирование» и API `GET/PUT /planner`. Создаст `specs/budget-planner/spec.md`.

### Изменяемые capabilities
- `tags`: мягкое удаление (`deleted_at`), `kind` и `order`, правило видимости категории по месяцам,
  удаление лимита вместе с категорией.
- `spending-limits`: один ежемесячный лимит на категорию, управление по `categoryId`. Прогресс-бары
  переезжают в блок 2. Уведомления о порогах 80/100 % не меняются.
- `analytics`: «Структура расходов по тегам» и «Доходы vs расходы» заменяются блоками 1–3 нового раздела.
  Календарь расходов на `/transactions` не меняется.

  - роуты в `internal/handler/router.go`, swagger.
- `workspace/finAns-frontend/`:
  - `src/features/analytics/pages/AnalyticsPage.tsx` переписывается; новые компоненты в
    `src/features/analytics/overview/`, `dynamics/`, `planner/`, `shared/` (`BudgetBar`, `Dropdown`, `MonthSwitcher`);

  - `src/index.css`: токен `--over`;
  - настройки проекта (категории): цвет и мягкое удаление; инвалидация `analytics`/`planner` в мутациях
    операций, тегов, лимитов и регулярных платежей.
- API: новые `GET /api/v1/analytics/month|year|range`, `GET/PUT /api/v1/planner`,
  `PUT/DELETE /api/v1/spending-limits/by-category/{categoryId}`; расширение ответа `GET /tags`

- Миграции: одна up/down пара, обратимая (down удаляет колонки и таблицу; мягко удалённые теги
  при откате остаются в БД как обычные).
