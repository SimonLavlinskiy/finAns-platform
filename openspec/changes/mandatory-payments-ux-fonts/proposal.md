# Подсветка регулярных платежей в календаре, подтверждение оплаты и локальные шрифты

## Зачем

Три независимых UX-доработки, накопившиеся по ходу использования: (1) календарь
расходов не показывает, что в один из будущих дней ожидается конкретный регулярный
платёж — приходится держать это в голове или проверять отдельную страницу; (2) кнопка
«Оплатить» сразу создаёт транзакцию без возможности поправить сумму и с неверной датой
(датой считается запланированный день платежа, а не фактический день оплаты); (3)
шрифты подключены через Google Fonts CDN, хотя уже скачаны локально и могут грузиться
без внешнего запроса.

## Что меняется

- Календарь расходов (`ExpensesCalendar`, месячный вид): будущий день, на который
  приходится `next_payment_date` активного регулярного платежа, подсвечивается
  отдельным стилем и показывает платёж (название, сумма) при наведении. Как только
  день наступил и прошёл — спецподсветка исчезает независимо от статуса оплаты
- **BREAKING** Кнопка «Оплатить» на странице регулярных платежей больше не создаёт
  транзакцию мгновенно — сначала открывает попап подтверждения с редактируемой суммой
- **BREAKING** Дата транзакции, создаваемой при оплате, — фактическая дата подтверждения
  (сегодня), а не `next_payment_date`; при этом сама дата следующего платежа
  по-прежнему считается от исходной запланированной даты (без изменений в этой логике)
- Локальные файлы шрифтов (`fonts/Comfortaa,Nunito/.../*-VariableFont_wght.ttf`)
  переносятся в исходники фронтенда и подключаются через `@font-face`; подключение
  через `fonts.googleapis.com` удаляется

## Non-цели

- Изменение правил начисления/продвижения `next_payment_date` — только источник даты
  самой транзакции меняется, расписание платежа не трогаем
- Подсветка регулярных платежей в годовом виде календаря (только помесячный/дневной)
- Редактирование тега/наименования в попапе подтверждения оплаты — редактируется
  только сумма (и, при необходимости, комментарий/ссылка — по аналогии с обычной
  формой транзакции), тег и наименование остаются от определения регулярного платежа
- Замена шрифтов на другие — только перенос уже выбранных Comfortaa/Nunito с CDN на
  локальные файлы, никаких визуальных изменений шрифтовой пары

## Capabilities

### Новые capabilities
- `mandatory-payment-calendar-highlight`: подсветка будущих дней с регулярным платежом на календаре расходов → `specs/mandatory-payment-calendar-highlight/spec.md`
- `local-fonts`: подключение шрифтов из локальных файлов вместо Google Fonts CDN → `specs/local-fonts/spec.md`

### Изменяемые capabilities
- `mandatory-payments`: требование «Отметка «Оплачено» с созданием транзакции» —
  добавляется попап подтверждения с редактируемой суммой, дата транзакции становится
  фактической датой подтверждения

## Влияние

- `workspace/finAns-backend/`: `internal/service/mandatory_payment_service.go`
  (`MarkPaid` — дата транзакции = `time.Now()` вместо `p.NextPaymentDate`, принимает
  опциональную сумму из запроса), `internal/dto/mandatory_payment.go` (новое поле
  запроса), `internal/handler/mandatory_payment_handler.go` (чтение тела запроса)
- `workspace/finAns-frontend/`: `ExpensesCalendar.tsx` (подсветка + hover для дней с
  регулярным платежом, дозагрузка списка регулярных платежей), новый компонент попапа
  подтверждения оплаты в `features/mandatory-payments/`, `MandatoryPaymentsPage.tsx`
  (кнопка «Оплатить» открывает попап вместо прямого вызова мутации), `index.html`/
  `src/index.css` (шрифты), новая директория со шрифтами в исходниках (например
  `src/assets/fonts/`)
- API: `POST /api/v1/mandatory-payments/:id/mark-paid` — тело запроса добавляет
  необязательное поле `amount` (копейки); дата транзакции больше не берётся из
  `next_payment_date`
- Миграции: не требуются
