## MODIFIED Requirements

### Requirement: Интерфейс добавления транзакции

Добавление транзакции SHALL открываться через кнопку «+ Добавить» в боковой панели
или модальном окне с быстрым переключением «Расход» / «Доход». Выпадающее окно выбора
категории SHALL раскрываться вниз с увеличенной максимальной высотой, показывая
больше вариантов без необходимости лишней прокрутки.

#### Scenario: Переключение категории в форме
- **WHEN** пользователь переключает категорию между «Расход» и «Доход» в форме
- **THEN** форма сохраняет введённые данные и меняет контекст категории

#### Scenario: Увеличенное окно выбора категории
- **WHEN** пользователь открывает выпадающий список выбора категории в форме
  добавления транзакции
- **THEN** список раскрывается вниз и показывает больше строк, чем помещалось ранее,
  без потери адаптивного позиционирования у края экрана

#### Scenario: Сохранение черновика при закрытии
- **WHEN** пользователь закрывает форму с несохранёнными данными
- **THEN** черновик сохраняется локально и восстанавливается при следующем открытии
  формы

## ADDED Requirements

### Requirement: Автодополнение наименования транзакции с автозаполнением полей

При вводе наименования транзакции (от 1 символа, с debounce) система SHALL предлагать
подсказки из истории транзакций текущего проекта (не глобально и не других
пользователей): наименования, у которых любое слово начинается с введённой подстроки
(регистронезависимо), без повторов одного и того же наименования, отсортированные по
алфавиту.

#### Scenario: Поиск по началу слова
- **WHEN** пользователь вводит «слив» в поле наименования
- **THEN** среди подсказок появляются «Сливки», «Мороженое из сливок», «Варенье из
  слив» — наименования, где хотя бы одно слово начинается на «слив»

#### Scenario: Дедупликация подсказок
- **WHEN** в истории проекта несколько транзакций с одинаковым наименованием
- **THEN** это наименование отображается в списке подсказок один раз

#### Scenario: Пустой ввод
- **WHEN** поле наименования пустое
- **THEN** подсказки не показываются

#### Scenario: Наименование без истории
- **WHEN** введённая подстрока не совпадает ни с одним сохранённым наименованием
- **THEN** подсказки не показываются, поля заполняются пользователем вручную

### Requirement: Автозаполнение суммы, категории и вида платежа по истории

При выборе подсказки наименования из истории система SHALL автоматически подставлять
сумму, категорию (тег) и вид платежа (Простой / Регулярный) из наиболее частой для
этого наименования комбинации «сумма + категория + вид платежа» в истории проекта;
все подставленные поля остаются доступны для ручного редактирования.

#### Scenario: Автоподстановка по самой частой комбинации
- **WHEN** пользователь выбирает подсказку наименования, у которого несколько
  сохранённых комбинаций сумма/категория/вид платежа с разной частотой использования
- **THEN** подставляется комбинация с наибольшим счётчиком использований

#### Scenario: Равная частота — берём последнюю по дате
- **WHEN** у наименования несколько комбинаций с одинаковой максимальной частотой
  использования
- **THEN** подставляется комбинация, использованная последней по дате

#### Scenario: Подставленные поля редактируемы
- **WHEN** после выбора подсказки поля суммы/категории/вида платежа автозаполнены
- **THEN** пользователь может вручную изменить любое из этих полей перед сохранением

### Requirement: Частота использования наименований отражает реальную историю

Частота использования комбинации «наименование + сумма + категория + вид платежа»,
используемая для автоподстановки, SHALL всегда отражать актуальное состояние истории
транзакций проекта — включая транзакции, сохранённые, отредактированные или удалённые
после последнего использования подсказки. Наименование становится доступным для
подсказок сразу после сохранения первой транзакции с этим наименованием.

#### Scenario: Наименование доступно сразу после первого сохранения
- **WHEN** пользователь впервые сохраняет транзакцию с новым наименованием
- **THEN** при следующем вводе этой же подстроки наименование уже появляется в
  подсказках

#### Scenario: Редактирование транзакции меняет частоту
- **WHEN** пользователь меняет сумму или категорию у ранее сохранённой транзакции,
  из-за чего одна из комбинаций «наименование + сумма + категория + вид платежа»
  перестаёт быть самой частой для этого наименования
- **THEN** при следующем выборе этой подсказки автоподстановка использует новую
  самую частую комбинацию, а не устаревшую

#### Scenario: Удаление транзакции уменьшает частоту
- **WHEN** пользователь удаляет транзакцию, которая была единственным использованием
  определённой комбинации для наименования
- **THEN** эта комбинация больше не предлагается для автоподстановки этого
  наименования
