# Отдельная страница аналитики: индекс свободы, Sankey, прогноз баланса и умные инсайты

## Зачем

Сейчас вся «аналитика» — это встроенный в `/transactions` календарь расходов по дням/месяцам.
Нет ответа на вопросы «куда реально утекают деньги», «трачу по необходимости или по
желанию», «хватит ли денег до зарплаты» и «когда я смогу купить то, что хочу».
Нужна отдельная страница `/analytics` с полноценным набором графиков и «умных»
виджетов, где флагманская метрика — **индекс свободы**: доля трат «по желанию»
(`specificity='simple'`) от всех расходов, в динамике по месяцам — единственная в
своём роде метрика, так как строится на уже размечаемых пользователем данных,
которых нет ни у одного стандартного финансового трекера.

## Что меняется

- Новая страница `/analytics` с навигационным пунктом «Аналитика» — вся функциональность
  этого change живёт **только там**, строго аддитивно: ни одна существующая страница
  (`/transactions`, `/planned-expenses`, `/mandatory-payments` и т.д.) не редактируется
  и не теряет ничего, новые виджеты только читают их данные через уже существующие API.
  Календарь расходов (`ExpensesCalendar`) остаётся на `/transactions` без изменений —
  никакого переноса
- Индекс свободы: трендовая линия доли «простых» (по желанию) трат от общих расходов
  по месяцам за последние 12 месяцев — флагманский виджет, самый заметный на странице,
  со слайдером-симулятором «что если» под графиком
- Коэффициент «жёсткости» бюджета: доля дохода, уходящая на обязательные платежи —
  второй индикатор рядом с индексом свободы
- Sankey-диаграмма: источники дохода → категории расходов → подкатегории → остаток
  (что отложено/не потрачено) за выбранный период
- Прогноз баланса: линия факт+прогноз на 30/60/90 дней вперёд на основе текущего
  баланса, запланированных регулярных платежей и тренда исторических доходов/расходов
- «Когда я смогу купить X?»: для товаров из вишлиста («Хочу купить») с указанной ценой
  — прогнозируемая дата, когда баланс дорастёт до этой суммы, на основе того же тренда,
  что и прогноз баланса
- Календарь по «настроению» трат: новый самостоятельный виджет на `/analytics`
  (не модифицирует и не заменяет `ExpensesCalendar.tsx` на `/transactions`) — цвет
  дня по доле impulse-трат, а не по сумме
- Умная лента инсайтов: 2-4 авто-сгенерированные текстовые фразы (аномалии
  месяц-к-месяцу по категориям, самая крупная покупка, новые теги)
- Сравнение периодов: «этот месяц vs прошлый» и «этот месяц vs тот же месяц год
  назад» по топ-5 категориям
- Оживление лимитов трат (`spending_limits`, таблица существует, backend не реализован):
  CRUD лимитов по тегам + прогресс-бары факт/лимит на странице аналитики
- Библиотека графиков: **Recharts** (см. `design.md` за обоснованием)
- Полный пересмотр требований `analytics` (v2) — они описывали только встроенный
  календарь, без отдельной страницы и без графиков из этого change

## Non-цели

- Сравнение расходов между участниками проекта («кто сколько потратил») — вне scope
- Мультивалютность в прогнозе/графиках
- История нескольких периодов оплаты по лимитам (аналогично `mandatory-payments`) —
  только текущий период
- Push-уведомления о лимитах и инсайтах — только в интерфейсе аналитики, без
  email/push
- Прогноз даты покупки для товаров вишлиста без указанной цены (`cost_kopecks = null`)
  — такие товары просто не участвуют в `savings-goal-forecast`
- Редактирование вишлиста/регулярных платежей со страницы аналитики — только чтение
  и прогноз, редактирование остаётся на своих страницах
- Настройка состава/порогов авто-инсайтов пользователем — набор правил фиксирован в v1

## Capabilities

### Новые capabilities
- `freedom-index`: тренд-линия доли трат «по желанию» vs «по необходимости» по месяцам + слайдер-симулятор «что если» → `specs/freedom-index/spec.md`
- `fixed-cost-ratio`: доля дохода, уходящая на обязательные платежи → `specs/fixed-cost-ratio/spec.md`
- `income-expense-sankey`: Sankey-диаграмма доход → категория → подтег → остаток → `specs/income-expense-sankey/spec.md`
- `balance-forecast`: прогноз баланса на 30/60/90 дней → `specs/balance-forecast/spec.md`
- `savings-goal-forecast`: прогнозируемая дата, когда накопится на товар из вишлиста → `specs/savings-goal-forecast/spec.md`
- `spending-mood-calendar`: календарь, окрашенный по доле impulse-трат за день → `specs/spending-mood-calendar/spec.md`
- `spending-insights`: авто-сгенерированная лента текстовых инсайтов → `specs/spending-insights/spec.md`
- `period-comparison`: сравнение текущего периода с прошлым/годом назад по топ-категориям → `specs/period-comparison/spec.md`
- `analytics-page`: каркас страницы `/analytics`, общий селектор периода, размещение виджетов → `specs/analytics-page/spec.md`

### Изменяемые capabilities
- `analytics`: требования «Структура расходов по тегам (v2)» и «Доходы vs расходы (v2)» удаляются как нереализованные — их закрывает новая Sankey-диаграмма; требование «Расходы по периодам» не меняется (календарь остаётся на месте)
- `spending-limits`: реализация CRUD лимитов и прогресс-баров (было полностью нереализовано, только таблица в БД)

`expenses-calendar` не меняется вообще — компонент остаётся на `/transactions` без
изменений. `planned-expenses` и `mandatory-payments` тоже не меняются — новые
виджеты только читают их данные через уже существующие `GET`-эндпоинты.

## Влияние

- `workspace/finAns-backend/`: новые эндпоинты аналитики (`freedom-index`,
  `fixed-cost-ratio`, `income-expense-sankey`, `balance-forecast`,
  `savings-goal-forecast`, `spending-mood-calendar`, `spending-insights`,
  `period-comparison`), CRUD `spending_limits` (`internal/handler`, `internal/service`,
  `internal/repository` — новые файлы)
- `workspace/finAns-frontend/`: новая `AnalyticsPage.tsx` + роут `/analytics`, пункт
  навигации в `AppLayout.tsx`, новая зависимость `recharts`, все виджеты — новые
  компоненты в `features/analytics/components/`. `ExpensesCalendar.tsx` и
  `TransactionsPage.tsx` не редактируются
- API: 8 новых `GET`-эндпоинтов аналитики + `GET/POST/PUT/DELETE /api/v1/spending-limits`
- Миграции: одна — `spending_limits.amount` остался `NUMERIC(15,2)` (рубли) с самой
  первой схемы и не был переведён на `BIGINT` (копейки) вместе с остальными
  денежными колонками в миграции `000002_add_tag_color_and_kopecks`; приводим к
  общему знаменателю той же миграцией-паттерном (`× 100`, `::BIGINT`)
