## ADDED Requirements

### Requirement: Календарь, окрашенный по доле impulse-трат

Система SHALL отображать альтернативный вид календаря на странице аналитики, где
цвет дня определяется долей расходов со специфичностью «Простой» (по желанию) за
этот день, а не суммой расходов.

#### Scenario: День почти целиком «по необходимости»
- **WHEN** в день расходы почти целиком имеют специфичность «Обязательный»
- **THEN** день окрашивается в цвет, близкий к «доходному» (низкая доля impulse)

#### Scenario: День почти целиком «по желанию»
- **WHEN** в день расходы почти целиком имеют специфичность «Простой»
- **THEN** день окрашивается в цвет, близкий к «расходному» (высокая доля impulse)

#### Scenario: День без расходов
- **WHEN** в день нет ни одной транзакции-расхода
- **THEN** день отображается нейтральным цветом плейсхолдера, не участвует в
  расчёте доли

#### Scenario: Отдельный компонент, не влияющий на основной календарь
- **WHEN** пользователь переключается между обычным календарём расходов
  (`ExpensesCalendar`) и календарём по «настроению» трат
- **THEN** переключение не влияет на состояние или поведение обычного календаря

### Requirement: REST API календаря по настроению трат

Backend SHALL предоставлять
`GET /api/v1/analytics/spending-mood-calendar?year=&month=`, возвращающий для
каждого дня месяца сумму «простых» расходов, общую сумму расходов и долю.

#### Scenario: Запрос календаря настроения
- **WHEN** клиент запрашивает `GET /api/v1/analytics/spending-mood-calendar?year=2026&month=7`
- **THEN** ответ `200` содержит по одному элементу на каждый день месяца с полями
  `day`, `simple_amount`, `total_expense`, `share` (`share = null`, если за день
  расходов не было)
