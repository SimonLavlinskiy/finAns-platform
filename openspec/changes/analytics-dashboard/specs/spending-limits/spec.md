## MODIFIED Requirements

### Requirement: Создание лимита трат

Пользователь SHALL задавать лимит расходов на тег за период: месяц, неделя или
произвольный диапазон (поля: тег, сумма, тип периода, `period_start`/`period_end`
при произвольном диапазоне). Управление лимитами SHALL быть доступно на странице
`/analytics`.

#### Scenario: Лимит на месяц
- **WHEN** пользователь создаёт лимит 10 000 ₽ на тег «Еда» за текущий месяц
- **THEN** лимит сохраняется в `spending_limits` и отображается в списке активных лимитов на `/analytics`

#### Scenario: Редактирование лимита
- **WHEN** пользователь меняет сумму существующего лимита
- **THEN** новая сумма сохраняется и сразу отражается в прогресс-баре

#### Scenario: Удаление лимита
- **WHEN** пользователь удаляет лимит
- **THEN** лимит и его прогресс-бар пропадают со страницы аналитики

### Requirement: Прогресс-бар лимита

Для каждого активного лимита система SHALL показывать прогресс-бар: потрачено /
осталось, с подсветкой при превышении. Потраченная сумма вычисляется по фактическим
транзакциям-расходам с этим тегом (включая подтеги) в пределах периода лимита.

#### Scenario: Прогресс в пределах лимита
- **WHEN** сумма расходов по тегу за период меньше лимита
- **THEN** прогресс-бар показывает потраченную и оставшуюся сумму в нейтральном цвете

#### Scenario: Превышение лимита
- **WHEN** сумма расходов по тегу за период превышает лимит
- **THEN** прогресс-бар подсвечивается красным и отображает превышение

#### Scenario: Расходы по подтегу учитываются в лимите родительского тега
- **WHEN** лимит задан на тег верхнего уровня «Еда», а транзакция привязана к
  подтегу «Еда / Кафе»
- **THEN** сумма транзакции учитывается в прогрессе лимита «Еда»

### Requirement: REST API лимитов трат

Backend SHALL предоставлять `GET/POST/PUT/DELETE /api/v1/spending-limits` для CRUD
операций и отдавать в ответе GET текущую потраченную сумму за период вместе с
данными лимита.

#### Scenario: Получение списка лимитов с прогрессом
- **WHEN** клиент запрашивает `GET /api/v1/spending-limits`
- **THEN** ответ `200` содержит список лимитов, для каждого — `amount` (лимит) и
  `spent` (фактически потрачено за текущий период)

## REMOVED Requirements

### Requirement: Уведомления о лимитах (v2)

**Reason**: Вынесено за scope этого change — на странице `/analytics` прогресс-бар
уже наглядно показывает превышение цветом; отдельные всплывающие уведомления о
достижении 80%/100% откладываются до появления общего центра уведомлений в
приложении (см. `notifications` v2 в roadmap), чтобы не дублировать механизм
уведомлений разово только для лимитов.
**Migration**: Нет данных для миграции — требование не было реализовано.
