## ADDED Requirements

### Requirement: Прогноз даты накопления на товар из вишлиста

Для каждого активного товара из «Хочу купить» с указанной ценой система SHALL
показывать прогнозируемую дату, когда баланс (при текущем темпе накопления)
достигнет цены товара.

#### Scenario: Товар с ценой ниже текущего баланса
- **WHEN** цена товара меньше или равна текущему балансу
- **THEN** система показывает, что накопления достаточно уже сейчас (без даты в будущем)

#### Scenario: Товар с ценой выше текущего баланса и положительным темпом накопления
- **WHEN** цена товара выше текущего баланса, а прогнозируемый темп накопления
  положителен
- **THEN** система показывает прогнозируемую дату достижения нужной суммы

#### Scenario: Отрицательный или нулевой темп накопления
- **WHEN** прогнозируемый темп накопления отрицателен или равен нулю (баланс не
  растёт или снижается)
- **THEN** система показывает «неизвестно» вместо даты, а не бесконечную или
  отрицательную дату

#### Scenario: Товар без указанной цены не участвует в прогнозе
- **WHEN** у товара вишлиста `cost_kopecks` не задан
- **THEN** товар не отображается в списке прогнозов накопления

#### Scenario: Только чтение вишлиста
- **WHEN** пользователь просматривает прогнозы накопления на странице аналитики
- **THEN** редактирование/добавление товаров недоступно на этой странице — только
  переход на страницу «Хочу купить»

### Requirement: REST API прогноза накопления

Backend SHALL предоставлять `GET /api/v1/analytics/savings-goals`, возвращающий для
каждого активного товара вишлиста с указанной ценой прогнозируемую дату достижения
суммы (или признак недостижимости).

#### Scenario: Запрос прогнозов накопления
- **WHEN** клиент запрашивает `GET /api/v1/analytics/savings-goals`
- **THEN** ответ `200` содержит список с полями `planned_expense_id`, `title`,
  `cost`, `projected_date` (`null`, если недостижимо при текущем темпе)
